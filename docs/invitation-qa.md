# 单级邀请专项验收边界

- 新邀请奖励默认 288 积分，后台可修改；每笔待发记录保存当时配置的数额，已发历史不改。
- 只查询受邀账号的直接邀请人，不遍历祖先，不计算团队业绩。A 邀请 B、B 邀请 C 时，C 的合格订单只奖励 B。
- 注册不给邀请人奖励。首个实付商品订单确认收货后进入至少 7 天观察期；积分兑换（包括只付运费）和零元订单不参与。
- 全额/部分退款取消未发奖励；处理中的售后暂缓结算，结案后再检查。已发奖励后的例外退款目前不自动追回邀请积分，沿用观察期规则；这不等于所有时间范围的退款回收均已实现。
- 无效/停用的邀请码明确拒绝；注册与赠券共用事务，同一个券配置为新人券和邀请券时只送一次。
- 重复完成通知、重复定时结算及多进程并发结算只发一次。已有账号不能通过资料接口改绑邀请人。

## 自动化验证

`test/invites.js` 必须在 DEMO_MODE=1 且全新隔离 DATA_DIR 执行；拒绝在已有用户的数据库执行。测试为合成数据，不调用真实供应商下单/退款。

专项覆盖 A/B/C 奖励隔离、直接好友计数、自邀脏数据防御、绑定篡改、停用/注销账号、失效邀请码、重复手机号、注册事务回滚、同券防重、退款、售后暂停、可配置数额、重复与多进程并发发奖。

`test/flows.js` 另测 HTTP 注册、资料接口、祖先页面不显示间接好友、后台改积分即时展示，以及正式环境的模拟短信禁用。
